Consumer lag is the gap between Kafka's log-end offset and a consumer group's committed
offset. It is a proxy for work the group has not acknowledged, not proof of completed
business processing. Left unmonitored, growing lag means stale downstream data and
silent failures when consumer groups die. Monitoring lag and group health is an
essential operational practice for production Kafka; **Klag is one way to ship those
signals to your observability stack.**

:::tip[Control collection load]
Request batching with `KAFKA_CHUNK_COUNT` and `KAFKA_CHUNK_DELAY_MS` spreads offset
requests across a collection cycle, helping control broker load on larger clusters.
:::

## Why Klag?

<CardGrid>
  <Card title="Lag velocity" icon="random">
    Know if lag is **growing or shrinking**, and catch problems before they escalate.
  </Card>
  <Card title="Time-based lag" icon="seti:clock">
    See lag in **seconds/minutes**, with time-to-close estimates, instead of raw message counts.
  </Card>
  <Card title="Hot partition detection" icon="warning">
    Find partitions with **uneven load** causing bottlenecks, via statistical outliers.
  </Card>
  <Card title="Group state tracking" icon="approve-check">
    Alert on **`preparing_rebalance`, `completing_rebalance`, `dead`, or `empty`** states.
  </Card>
  <Card title="Data loss prevention" icon="error">
    Alert **before lag exceeds retention** and messages are lost forever.
  </Card>
  <Card title="Request batching" icon="setting">
    Safely monitor **large clusters** without overwhelming brokers.
  </Card>
</CardGrid>

## Get started in one command

```bash
docker run -e KAFKA_BOOTSTRAP_SERVERS=broker.example.com:9092 \
           -e METRICS_REPORTER=prometheus \
           -p 8888:8888 \
           themoah/klag:latest
```

Replace `broker.example.com:9092` with a broker address that resolves and is reachable
from inside the Klag container. Use Docker network or service DNS for Kafka in another
container. On Docker Desktop, `host.docker.internal:9092` reaches Kafka on the host;
on Linux Docker, add `--add-host=host.docker.internal:host-gateway` (or use the host
gateway IP directly).

Metrics land at `http://localhost:8888/metrics`. See the [Quick Start](/getting-started/quick-start/)
for native image, Helm, and Docker env-file options.

## Or let your agent do it

In Claude Code, add the Klag plugin and run the installer:

```txt
/plugin marketplace add themoah/klag
/plugin install klag@klag
/klag:install
```

It detects Docker, your kube context, Helm, ArgoCD/Flux and Strimzi, deploys accordingly,
and verifies that lag metrics actually arrive. Copilot, Codex, Cursor, OpenCode and other
agents are covered too — see [Agent Setup](/ai/agent-setup/).

## Built for AI-native operations

Klag exposes an opt-in, read-only [MCP endpoint](/ai/mcp/) so SRE and dev agents can
query lag, find lagging groups, and run composite `diagnose` checks, served from an
in-memory snapshot, never touching your brokers. Installation and connection are
agent-driven too — see [Agent Setup](/ai/agent-setup/).
